Where an AI memory tool lost a new user.

I planned to test context separation. The setup failure became the more useful finding.

01

Original test

Would one brand voice leak into another?

I work across accounts with writing rules that often conflict. The product promised to keep each client’s context separate.

The plan was simple: build two opposite brand profiles, generate under each one, then switch between Claude and ChatGPT. I never reached that stage.

02

What happened

01Connected

Notion linked successfully.

02Marked ready

The product said setup was complete.

03Asked for facts

Three answers came back “restricted.”

04Checked the vault

Page bodies had never arrived.

03

Diagnosis

Four messages pushed the user the wrong way.

01

“Restricted” hid the real state.

It sounded like a permission problem. The information had never been imported.

02

“All set” appeared too early.

A successful connection was presented as a successful import.

03

“Time saved” had no evidence.

The dashboard showed saved time while the memory count stayed at zero.

04

Metadata became a false profile.

The system inferred a working style from schema and sample rows, not the notes I wrote.

04

Recommendations

Three copy fixes. One product fix.

Message

Replace “restricted” with a neutral “nothing found” state and name the active filters.

Setup

Confirm the connection first. Call setup complete only after content arrives.

Metric

Hide time saved until the product has retrieved something.

Product

Import page bodies, not only titles and schema.

05

Validation

“The strongest report the team had received.”

Founder response, paraphrased to protect the private conversation

The founder checked the logs, confirmed the findings and said the integration problems were already being fixed.

The original context-separation test remains unfinished. This case study does not claim that feature failed.
